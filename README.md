# Travel Planner Agent — a durable AI agent on Temporal

A tiny, readable travel-planning assistant that shows the **canonical AI-agent
pattern** — a ReAct loop (reason → act → observe → repeat) — made **durable,
retryable, and pausable-for-humans** by Temporal, with **no agent framework**.

The agent helps a traveller go from *"where should I go?"* — or *"I'd like to
travel for an event"* — all the way to a booked trip. It supports two flows:

**Travel for an event** (the classic goal-driven path):

- **find an event** — `search_events` finds festivals, concerts, sports, and
  conferences by city and month.
- **search flights** around the event's dates, then
- **invoice the chosen flight** — `create_invoice`, gated by a human confirmation.

**Plan a full trip** (the richer path):

- **understand destinations** — `research_destination` runs a live, multi-step
  web-research pass (plan → parallel searches → synthesize a cited guide).
- **search flights & hotels** — quick catalog lookups over a seeded database.
- **build an itinerary** — durable, conversation-scoped state the traveller
  assembles across the chat.
- **book the trip** — a human-in-the-loop approval gate before anything is booked.

> Data split, on purpose: **flights, hotels, destinations, and attractions are
> seeded** in Postgres (deterministic, offline, demo-safe), while **destination
> intelligence is live** — `research_destination` uses Claude's built-in web
> search, so the guides are current and cited. No third-party flight API key
> needed.

This is a fork of the canonical music-store support-agent demo, re-themed to
travel — the Temporal primitives it teaches are identical.

## The one file to read

`python/workflows/agent.py` **is** the demo. The agentic loop is just a `while`
loop; Temporal is what makes it durable:

```
01 Receive input   → a chat message (a Temporal update)
02 Plan            → call the LLM as an Activity (retryable)
03 Execute tools   → tool calls as Activities (search_flights, add_to_itinerary…)
04 Persist state   → the conversation + itinerary live in workflow state (durable)
05 Loop / terminate→ keep looping until the model answers with no tool call
```

Everything else is supporting cast:

| Path | What it is |
|------|------------|
| `python/workflows/agent.py` | `TravelAgentWorkflow` — the durable ReAct loop + HITL + research fan-out |
| `python/activities/llm.py` | The LLM call as an Activity (Anthropic or OpenAI). Temporal owns retries. |
| `python/activities/tools.py` | Tool dispatch → the SQL functions. |
| `python/activities/db.py` | Plain parametrized SQL over the travel dataset. |
| `python/activities/research.py` | The `research_destination` pipeline steps (clarify / plan / web-search / write). |
| `python/prompts.py` | The system prompt + tool definitions + research prompts. |
| `web/gateway.py` | A thin HTTP gateway that drives the workflow by string name. |
| `web/index.html` + `web/app.js` | The chat UI (vanilla JS, no build step). |
| `db/seed.sql` | The seeded dataset (generated by `db/generate_seed.py`). |

## What it demonstrates (the Temporal beats)

1. **The agent is a loop.** `agent.py` — add a tool, the loop is unchanged. The
   universal pattern SAs reuse.
2. **Durable state, no database for it.** The conversation and the **itinerary**
   live in workflow state. A new conversation = a new workflow ID = a clean
   slate. No cross-session leakage, no reset between demos.
3. **Human-in-the-loop pauses.** `create_invoice` and `book_trip` park the
   workflow on a confirmation (`await workflow.wait_condition`) — the pause is
   **durable**, surviving worker restarts. The UI shows the tool name + args +
   Confirm. Same mechanism gates `research_destination`'s clarifying questions.
4. **Retries you didn't write.** LLM and tool calls are Activities with explicit
   `RetryPolicy`. A rate-limit or a DB blip just retries with backoff and
   recovers. A **non-retryable** business decline (booking the same flight twice)
   fails fast and the agent explains it.
5. **Crash recovery / parallel fan-out.** `research_destination` fans out N web
   searches as **parallel Activities**. Kill the worker mid-fan-out and restart:
   only the unfinished searches re-run — completed ones replay from history.
6. **Injectable failure.** The Demo-controls drawer has a per-conversation LLM
   kill-switch: flip it and every LLM call retries until you flip it back.

## Quick start (local)

Prereqs: Docker, the [Temporal CLI](https://docs.temporal.io/cli), and
[`uv`](https://docs.astral.sh/uv/). Put your `ANTHROPIC_API_KEY` in `.env`
(copy `.env.example`).

```bash
make up      # postgres + temporal dev server + worker + gateway + web UI
```

Then open:

- **chat UI** → http://localhost:5173
- **Temporal UI** → http://localhost:8233
- **gateway** → http://localhost:8000

`make down` stops everything. `make status` shows what's running.

### Try it

Event flow (the classic path):

- *"I'd like to travel for an event."* → *"Auckland in March"* → `search_events`
  (finds the Pasifika & Auckland Arts festivals)
- *"LA"* → `search_flights` around the event → *"Invoice me for the cheapest."*
  → `create_invoice` (Confirm gate)

Full-trip flow:

- *"Where should I go in Europe for food and beaches?"* → `search_destinations`
- *"Do a deep research pass on 5 days in Tokyo for a first-timer who loves food."*
  → `research_destination` (watch the parallel fan-out in the progress card)
- *"Add the cheapest flight and a hotel under $200, then book it."*
  → `add_to_itinerary` → `book_trip` (approval gate)

> Seeded flight dates span 2026 (**03-14, 06-13, 09-12, 09-19, 10-03, 12-19**);
> origins include SFO, LAX, JFK, ORD, SEA, MIA, LHR, CDG, FRA, DXB, SIN, HKG, SYD.
> Flight search is date-tolerant (falls back to the same month), so an event's
> dates still return flights. ~49 destinations and 82 events across every region —
> and `research_destination` works for *any* place (it's live web search).

### The demo money-shots

```bash
make kill-worker   # mid-research: the loop freezes…
make worker        # …and resumes on the exact next step (unfinished searches only)

make kill-db       # mid-turn: the tool activity retries with backoff (watch the UI)
make db            # …and the next retry just succeeds
```

Or open **Demo controls** (top-right) and flip the **LLM API** switch to simulate
a provider outage — the current turn's LLM calls retry until you flip it back.

## Regenerating the dataset

The seed is generated deterministically:

```bash
make seed          # → db/seed.sql  (~49 destinations, 245 attractions, 196 hotels, 82 events, ~7,500 flights)
```

Edit `db/generate_seed.py` and re-run. The 20 headline cities have hand-curated
attractions and hotels; the long tail is generated from templates. Flights run
from 13 major origins to every destination (both directions, three dates). All
generation uses a fixed RNG seed, so the committed `seed.sql` is byte-stable.

## Configuration

All via env (`.env` at the repo root; see `.env.example`):

- `ANTHROPIC_API_KEY` (or set `LLM_PROVIDER=openai` + `OPENAI_API_KEY`)
- `ANTHROPIC_MODEL` (default `claude-sonnet-4-6`)
- `TEMPORAL_ADDRESS` / `TEMPORAL_API_KEY` / TLS — local dev server by default,
  Temporal Cloud via env.
- `RESEARCH_SEARCHES` (default 6) — how many parallel searches per research pass.
- `DB_URL` — the seeded Postgres.
